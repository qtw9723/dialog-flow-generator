# 레퍼런스 학습 정책

## 개요

레퍼런스 학습 정책(Reference Learning Policy)은 사용자가 제공한 레퍼런스 문서를 기반으로 맞춤형 생성(Generation) 모델을 구축하는 프레임워크입니다. 이 정책은 레퍼런스 데이터의 등록, 학습, 검증 프로세스를 정의하여 안정적이고 효율적인 학습 파이프라인을 보장합니다.

---

## 정책 (Policy)

### 1. 레퍼런스 등록 및 수정

- **레퍼런스 추가**: 사용자는 특정 도메인의 레퍼런스 문서를 시스템에 업로드할 수 있습니다.
  - 레퍼런스는 문제-답변 쌍의 형태로 구조화되어야 합니다.
  - 각 레퍼런스는 고유한 ID와 메타데이터(생성일, 수정일 등)를 포함합니다.

- **레퍼런스 수정**: 기존 레퍼런스의 콘텐츠를 업데이트할 수 있습니다.
  - 수정 시 이전 버전은 추적되며, 변경 이력이 기록됩니다.
  - 수정된 레퍼런스는 재학습 대상이 됩니다.

- **레퍼런스 삭제**: 더 이상 필요 없는 레퍼런스는 시스템에서 제거할 수 있습니다.
  - 삭제된 레퍼런스는 학습 데이터에서 제외됩니다.

### 2. 학습 방식

- **통합 학습 (Batch Learning)**: 
  - 여러 개의 레퍼런스를 한 번에 처리하여 모델을 학습합니다.
  - 학습 과정에서 각 레퍼런스는 벡터화되고 임베딩 공간에 저장됩니다.
  - 학습 완료 후 상태는 `completed`로 업데이트됩니다.

- **증분 학습 (Incremental Learning)**:
  - 새로운 또는 수정된 레퍼런스만 학습하여 효율성을 높입니다.
  - 기존 학습 데이터는 유지되며, 새로운 데이터만 추가됩니다.

- **벡터화 및 임베딩**:
  - 각 레퍼런스의 텍스트는 임베딩 모델을 사용하여 벡터로 변환됩니다.
  - 벡터는 벡터 데이터베이스에 저장되어 빠른 검색을 가능하게 합니다.

### 3. 학습 데이터 관리

- **데이터 저장소**:
  - 원본 레퍼런스: 메타데이터와 함께 저장소에 보관됩니다.
  - 임베딩 벡터: 별도의 벡터 데이터베이스에 저장되어 유사도 검색에 사용됩니다.

- **데이터 일관성**:
  - 학습 중 레퍼런스가 수정되면, 해당 벡터는 자동으로 업데이트 대기 상태로 설정됩니다.
  - 일관성을 유지하기 위해 동시성 제어 메커니즘이 적용됩니다.

- **버전 관리**:
  - 각 레퍼런스의 버전이 추적되므로, 필요시 이전 버전으로 복원할 수 있습니다.

### 4. 생성(Generation) 전 검증

- **필수 조건**:
  - 생성(Generation)을 수행하기 전에 최소 1개 이상의 학습 완료된 레퍼런스가 존재해야 합니다.
  - 모든 레퍼런스는 상태가 `completed`이어야 합니다.

- **검증 프로세스**:
  - 생성 요청 시 시스템은 자동으로 학습 데이터의 준비 상태를 확인합니다.
  - 학습이 미완료된 데이터가 있으면 생성 요청은 거부됩니다.

- **에러 처리**:
  - 학습 실패로 인한 상태 `invalid`인 레퍼런스는 수정 및 재학습 대상입니다.
  - 사용자에게 구체적인 에러 메시지를 제공하여 문제 해결을 지원합니다.

## 워크플로우 (Workflow)

### Step 1: 레퍼런스 업로드/수정

1. 사용자가 레퍼런스 파일 또는 텍스트를 제출합니다.
2. 시스템이 레퍼런스를 검증하고 저장합니다.
3. 레퍼런스 상태는 `pending`으로 설정됩니다.

**사용자 액션**:
```
레퍼런스 업로드 → 시스템 검증 → 저장 완료 (상태: pending)
```

### Step 2: 통합 학습 실행

1. 사용자가 학습 실행 명령을 발행합니다.
2. 시스템이 `pending` 상태의 모든 레퍼런스를 수집합니다.
3. 각 레퍼런스를 벡터화하고 벡터 데이터베이스에 저장합니다.
4. 학습 완료 후 상태를 `completed`로 업데이트합니다.
5. 학습 실패 시 상태를 `invalid`로 설정하고 에러 메시지를 기록합니다.

**시스템 액션**:
```
학습 시작 → 벡터화 → 저장 → 상태 업데이트 (완료 또는 실패)
```

### Step 3: 생성(Generation) 실행

1. 사용자가 생성 요청을 제출합니다.
2. 시스템이 학습 완료 상태(`completed`)의 레퍼런스 존재 여부를 확인합니다.
3. 사용자의 쿼리를 기반으로 유사한 레퍼런스를 벡터 데이터베이스에서 검색합니다.
4. 검색된 레퍼런스를 context로 사용하여 응답을 생성합니다.
5. 생성 결과를 사용자에게 반환합니다.

**사용자 액션**:
```
쿼리 입력 → 검증 (학습 완료 확인) → 유사도 검색 → 생성 → 결과 반환
```

## 상태 정의 (Status Definition)

| 상태 | 설명 | 다음 단계 |
|------|------|---------|
| `pending` | 학습되지 않음. 방금 업로드되거나 수정된 레퍼런스가 이 상태입니다. | 통합 학습 실행 시 `completed` 또는 `invalid`로 전환 |
| `completed` | 학습 완료. 레퍼런스가 성공적으로 벡터화되어 벡터 데이터베이스에 저장되었습니다. | 생성(Generation)에 사용 가능 |
| `invalid` | 학습 실패. 벡터화 또는 저장 과정에서 오류가 발생한 레퍼런스입니다. | 레퍼런스 수정 후 재학습 필요 |

## 구현 세부사항 (Implementation Details)

### 데이터베이스 계층 (Data Layer)

- **저장소**: `/src/db/schema.ts`에서 레퍼런스 및 학습 상태 스키마 정의
- **작업**: `/src/db/actions.ts`에서 CRUD 작업 및 상태 관리 로직 구현

### 서비스 계층 (Service Layer)

- **학습 서비스**: `/src/services/learningService.ts`에서 벡터화 및 학습 로직 구현
- **생성 서비스**: `/src/services/generationService.ts`에서 검색 및 생성 로직 구현

### API 계층 (API Layer)

- **레퍼런스 API**: `/src/api/references.ts`에서 업로드, 수정, 삭제 엔드포인트 제공
- **학습 API**: `/src/api/learning.ts`에서 학습 실행 엔드포인트 제공
- **생성 API**: `/src/api/generation.ts`에서 생성 요청 엔드포인트 제공

### 검증 계층 (Validation Layer)

- **타입 검증**: `/src/utils/validation.ts`에서 입력 데이터 검증
- **상태 머신**: 상태 전환 규칙 및 검증 로직 구현

---

## 요약

레퍼런스 학습 정책은 사용자 제공 데이터를 기반으로 효율적이고 안정적인 생성 시스템을 구축하기 위한 포괄적인 프레임워크입니다. 명확한 상태 관리, 체계적인 워크플로우, 그리고 검증 메커니즘을 통해 시스템의 신뢰성과 확장성을 보장합니다.
