DialogFlow 챗봇의 NLP 학습 데이터를 만들어라. 인텐트(대분류)와 엔티티(세부 구분)다.

[시나리오]
1. 시나리오명: 매장 예약
   진입 발화: 예약하고 싶어요
   수집 항목: 매장명, 날짜, 인원
   완료 결과: 예약 완료 안내
   갈림길: 신용카드라고 말한 경우 / 체크카드라고 말한 경우
2. 시나리오명: 배송 조회
   진입 발화: 배송 어디쯤이에요
   수집 항목: 주문번호
   완료 결과: 배송 상태 안내
   갈림길: (없음)

[ESD 필드(발화에서 값을 뽑을 후보)]
- reservation: store_id, visit_date

[인텐트 — 시나리오 1:1, 이름은 아래 목록으로 확정]
1. 매장예약  ← 시나리오 "매장 예약"
2. 배송조회  ← 시나리오 "배송 조회"
- **이름을 새로 짓지 마라.** 위 목록의 이름을 위 순서 그대로 쓴다(플로우 조건이 이 이름을 참조한다).
- 인텐트마다 어터런스(example) 20~30개. 진입 발화를 시드로 쓰되 그대로 복사하지 말고 확장하라.
- **다른 인텐트와 겹치는 예문을 만들지 마라** — 겹치면 NLP가 둘을 구분할 수 없다.

[엔티티 — 두 종류]
- 분류 엔티티(type "synonyms"): 인텐트 안에서 무엇을 묻는지 가른다. 시나리오의 수집 항목 선택지나 발화로 갈리는 갈래에서 뽑는다. 예: 엔티티 "배송정보"의 value가 "예상도착일"·"배송상태".
- **각 시나리오의 "갈림길" 중 사용자 발화로 갈리는 것마다 분류 엔티티를 반드시 하나 만들어라.** 갈래 각각이 value가 된다.
  예: 갈림길이 "신용카드라고 말한 경우 / 체크카드라고 말한 경우"면 → 엔티티 "카드종류", value "신용카드"·"체크카드"(동의어에 "신용"·"크레딧"·"체크"·"직불" 등).
  이 엔티티가 없으면 플로우가 그 갈래를 고를 수단이 없다 — 빠뜨리지 마라.
  (변수 값·조회 성공 실패처럼 발화와 무관한 갈림길은 만들지 않는다.)
- 수집 엔티티(type "patterns"): 발화에서 값을 뽑는다. 숫자·단위처럼 정형이면 정규식을 value의 synonyms에 넣는다. 예: value "개", synonyms ["(?:[1-9][0-9]?|한|두|세)\\s*개"].
- **솔루션에 등록된 레코드를 가리키는 엔티티(메뉴처럼 value가 ID여야 하는 것)는 만들지 마라.** 그 ID를 알 수 없다.
- 뽑을 근거가 없으면 엔티티를 비워도 된다(빈 배열).

[어터런스 작성 지침 — 인텐트]
- **인텐트 예문에는 오타를 넣지 마라.** 맞춤법에 맞는 정상 문장만 쓴다. 오타 변형은 엔티티 동의어의 몫이다.
- 말하는 방식을 넓혀라 — 명령형("배송 조회해줘"), 의문형("배송 언제 와요?"), 명사구("배송조회"), 구어 축약("배송 어디쯤"), 존댓말과 반말, 짧은 발화와 긴 발화.
- **예문의 3분의 1 이상은 기능 이름을 말하지 않고 상황·증상·목적만 말하는 발화로 채워라.** 실제 사용자는 "A/S 접수할게요"가 아니라 "세탁기가 안 돌아가요"라고 말한다. 시나리오의 기능 단어(접수·조회·신청·안내 같은 말)가 **한 번도 안 나오는** 문장을 반드시 섞어라.
  · 인텐트 "AS접수" → "세탁기가 안 돌아가요", "냉장고에서 소리가 나요", "화면이 안 켜져요", "물이 새요"
  · 인텐트 "배송조회" → "물건이 아직 안 왔어요", "언제쯤 도착해요?"
  · 인텐트 "반품신청" → "이거 돌려보내고 싶어요", "사이즈가 안 맞아요"
  이런 발화가 없으면 사용자가 증상만 말했을 때 **엉뚱한 인텐트로 분류된다**(실측: "세탁기가 안 돌아가요"가 FAQ 인텐트로 갔다).
- **"안내"·"문의"·"FAQ"처럼 포괄적인 인텐트는 예문을 그 기능에 딱 붙여라.** 일반적인 질문 어휘("궁금해요", "문의합니다", "알려주세요")만으로 이루어진 예문을 늘리면 다른 인텐트의 발화까지 빨아들인다.
- 한 인텐트 안에서 예문이 서로 지나치게 비슷하지 않게 하라.
- **같은 문장 틀에 숫자·값만 바꿔 개수를 채우지 마라.** ("예약번호 12345 확인해줘", "예약번호 67890 확인해줘" … 는 사실상 예문 1개다.) 값이 들어가는 예문은 2~3개면 충분하고, 나머지는 문장 구조를 바꿔라.

[동의어 작성 지침 — 엔티티]
- 정상 표현만 나열하지 마라. **오타·구어 변형을 일부러 섞어라**:
  · 한글 오타/자모 오류 — "위치"에 대해 "윛치", "우치"
  · 초성 탈락·붙여쓰기 — "전화번호"에 대해 "저나번호", "버노"
  · 영문 표기와 그 오타 — "addr", "addres", "time", "open"
  · 구어·축약 — "메뉴판", "주차"
- **동의어는 value 하나당 최대 10개**까지만 쓴다. 그 이상은 업로드 CSV(13컬럼 고정)에서 잘린다.

[출력 — JSON만, 다른 텍스트 금지]
{
  "intents": [{ "name": "<인텐트명>", "examples": ["<어터런스>", "..."] }],
  "entities": [{ "name": "<엔티티명>", "type": "synonyms" | "patterns",
                 "values": [{ "value": "<값>", "synonyms": ["<동의어>", "..."] }] }]
}
