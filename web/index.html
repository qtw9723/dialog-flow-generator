실운영 아님 · 스크립트된 LLM 응답

LLM이 설계하고, 코드가 검증합니다

요구 문서 → 대화 흐름 JSON 생성기의 검증·보정·확장 구간을, 실제 소스를 그대로 실행한 기록입니다. LLM 호출 2번만 스크립트로 대신했습니다.

검증 결과가 바뀌는 과정

같은 검증 함수가 세 번 돌았습니다. 코드로 고칠 수 있는 오류는 고치고, 의미가 필요한 오류만 LLM에게 되돌립니다.

① 1차 설계 직후

  • 오류노드 "n2": 끊긴 next 참조 "ghost"
  • 오류루프 "n3": 본문에 탈출 변수 "reason_ok"를 설정할 set 노드가 없음
  • 오류노드 "n6": 미지의 노드 종류 "teleport"
오류 3미지 종류·끊긴 참조·무한 반복 가능 루프

② 자동 보정 후

  • 오류루프 "n3": 본문에 탈출 변수 "reason_ok"를 설정할 set 노드가 없음
오류 1코드가 못 고치는 건 LLM에 되돌립니다

③ 재설계 후

  • OK모든 검사 통과
오류 0여기서야 확장 단계로 넘어갑니다

확장은 LLM 없이

검증을 통과한 설계는 노드 스펙 골격에 값을 채우는 방식으로 결정론적으로 펼쳐집니다.

6LLM이 설계한 노드
12확장 후 노드 (코드가 인사·초기화·폴백 등을 추가)
0확장에 쓴 LLM 호출
3생성된 대화 묶음
반복 노드 — "loop"(의도)가 실제 노드로 결정론 변환된 결과

검증된 항목

데모 스크립트가 실행 끝에 확인하는 항목입니다.

  • PASS미지의 노드 종류를 제거
  • PASS끊긴 next 참조를 제거
  • PASS탈출 변수가 없는 반복을 적발
  • PASS보정 불가 오류는 LLM에 되돌림
  • PASS재설계 후 검증 통과
  • PASS인사 노드를 코드가 보장
  • PASS확장 결과 id 중복·끊긴 참조 0
